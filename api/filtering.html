Filtering

Filtering narrows a collection before pagination and sorting. Use the exact parameter names and value formats published for each route; filters are a query aid, never a substitute for authorization or tenant isolation.

Filter behavior

RuleClient guidance
Tenant scopeEvery result is constrained by the authenticated tenant even when no tenant filter is supplied.
Unknown parametersDo not depend on ignored parameters. Remove them unless the route contract accepts them.
Exact valuesUse canonical ids, ISO-8601 timestamps, documented enum values and exact currency codes.
RangesConfirm whether boundaries are inclusive and use UTC for time ranges.
Empty filtersExpect a bounded default page rather than an unbounded export.

Example query

curl --get "$PESAGUARD_API_URL/api/v1/discrepancies" \
  --data-urlencode "status=open" \
  --data-urlencode "provider_id=provider_123" \
  --data-urlencode "created_from=2026-09-01T00:00:00Z" \
  --data-urlencode "created_to=2026-09-02T00:00:00Z" \
  --data-urlencode "page=1" \
  --data-urlencode "limit=50" \
  -H "Authorization: Bearer $PESAGUARD_ACCESS_TOKEN"

Safe filtering workflow

  1. Start with a narrow time range and a small limit.
  2. Confirm response metadata and tenant context.
  3. Add one filter at a time and record the resulting count.
  4. Use pagination and stable sorting for exports or reconciliation jobs.
