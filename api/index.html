API

API reference

The PesaGuard API exposes tenant-scoped operations for provider configuration, reconciliation, communications and operational telemetry. The OpenAPI document defines the request surface; this guide explains the behavior clients must preserve in production.

GET/openapi.json
curl -sS "$PESAGUARD_API_URL/openapi.json" | python -m json.tool | head

Start with the contract

Fetch the specification from the same deployment you intend to call. A checked-in copy is useful for review, but the running deployment is authoritative because routes, security configuration and compatibility aliases can vary by environment.

Request lifecycle

  1. Resolve the correct environment base URL.
  2. Authenticate and establish tenant context.
  3. Validate the request before reading or mutating state.
  4. Apply authorization, rate limits and idempotency policy.
  5. Process the operation and return a correlation id.
  6. Handle errors according to status and retry semantics.

Operational expectations

Tenant isolation

Credentials and server-side membership determine data visibility. A client filter cannot widen a tenant boundary.

Durable writes

Use idempotency keys for retried writes and persist the response or outcome needed to reconcile a retry.

Observable calls

Record method, route, status, latency and request id without logging authorization headers or sensitive payloads.

A static copy of the contract lives at api-reference/openapi.json. The running deployment is authoritative if the two ever differ.
