API

Pagination

List endpoints return a bounded page of tenant-scoped items plus metadata. Pagination keeps response size predictable, protects the service under high-volume reconciliation, and gives clients a deterministic way to finish a scan.

200list envelope
{
  "items": [],
  "page": 1,
  "limit": 25,
  "total": 0,
  "total_pages": 0
}

Page parameters

ParameterMeaningGuidance
pageOne-based page numberStart at 1 and advance only after a successful response.
limitItems requested per pageUse a documented bounded value; the server may cap it.
totalMatching item countTreat as a point-in-time estimate for changing collections.
total_pagesCalculated page countUse it as the loop bound, not an empty page guess.

Iteration example

for (let page = 1; page <= totalPages; page += 1) {
  const response = await get(`/api/v1/discrepancies?page=${page}&limit=50`);
  consume(response.items);
}

Pass page and limit as query parameters; treat total_pages as the loop bound rather than paginating until an empty page. Filtering and sorting parameters, where supported, are documented per endpoint in the OpenAPI contract.

Consistency and exports

For a changing collection, combine a stable sort with a time or id boundary and record the query used. If an export must be complete and reproducible, prefer a server-side export job or snapshot contract over holding a moving page count in memory. Retry a failed page without changing filters, sort or page size.
