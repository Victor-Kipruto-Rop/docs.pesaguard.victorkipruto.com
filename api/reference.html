API

Reference

The authoritative API contract is the OpenAPI document served by the deployment you are calling. This page explains how to retrieve, compare and use that contract without treating generated schema as a substitute for runtime behavior.

GET/openapi.json
curl -sS "$PESAGUARD_API_URL/openapi.json" -o openapi.json

Contract facts

  • Specification format: OpenAPI 3.0.3.
  • Document version: 2.0.0 in the checked-in contract.
  • Security scheme: HTTP bearer with JWT format.
  • Every error should be handled through the normalized envelope and request id.
  • Some paths are rooted at /api/v1; follow the exact path published by the running deployment.

Retrieving and reviewing the document

curl --fail "$PESAGUARD_API_URL/openapi.json" \
  -H "Authorization: Bearer $PESAGUARD_ACCESS_TOKEN" \
  -o openapi.json
node -e "JSON.parse(require('fs').readFileSync('openapi.json'))"

Pin a reviewed contract in client generation and compare it during deployment. Treat a new path as additive only after checking authorization, tenant scope, pagination, errors, rate limits and idempotency. A schema change can still be behaviorally breaking if defaults or validation rules change.

Generated clients

Generated code is a starting point. Add timeouts, bounded retries, request-id logging, token renewal, idempotency keys for writes and explicit handling for 401, 403, 409, 429 and 5xx responses.
