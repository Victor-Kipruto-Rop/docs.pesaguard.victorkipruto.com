Changelog

August 2026

August records the preparation of the documentation and operational contract that supports the public PesaGuard integration surface.

Recorded changes

DOCUMENTATION · FOUNDATION

API reference structure prepared

Established the API overview and topic structure for authentication, errors, idempotency, pagination, rate limits, filtering, sorting, request validation, versioning and the OpenAPI reference.

Why it matters: Integrations now have a consistent place to verify request behavior, recovery rules and operational constraints.

OPERATIONS · GUIDANCE

Tenant and reconciliation principles made explicit

Documentation emphasizes tenant isolation, durable writes, idempotent retries, stable ordering, bounded pagination, auditability and reconciliation correctness.

Action: Use these principles when reviewing client retries, exports and background workers.

Release impact

No runtime endpoint change is asserted by this documentation record. Check the OpenAPI contract and deployment release notes for implementation-specific changes.

Operational review checklist

ConcernReview question
IsolationAre reads, writes, exports, caches and replay workers tenant-scoped?
RetriesDo workers preserve idempotency keys and avoid duplicate financial records?
OrderingDo exports use stable sorting and bounded pagination?
RecoveryCan operators trace an outcome using request, event and reconciliation ids?
SecretsAre production credentials scoped, stored server-side and rotatable?

Adoption guidance

Teams adopting the documentation should turn the principles into integration tests and operational checks. The guidance is most valuable when it is attached to deployment reviews, background-worker capacity tests and reconciliation runbooks.
