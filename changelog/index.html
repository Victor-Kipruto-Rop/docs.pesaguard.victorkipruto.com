Changelog

Changelog

A dated record of documentation, API contract and operational changes that can affect an integration. Each entry identifies the audience, migration impact and source of truth so teams can decide whether action is required.

How to read this page. Product behavior changes require an implementation source or release reference. Documentation-only entries improve guidance without changing runtime behavior. When a release affects compatibility, also read breaking changes and the relevant API page.

Change categories

CategoryMeaningExpected action
AddedNew endpoint, guide, field, capability or supported workflow.Adopt when useful; check permissions and limits.
ChangedExisting behavior, guidance, default or operational expectation changed.Review integration tests and deployment configuration.
DeprecatedStill available but scheduled for removal or replacement.Plan migration within the announced support window.
FixedIncorrect behavior, contract wording or documentation gap corrected.Re-test affected workflows.
SecurityCredential, tenant isolation, audit or exposure-related change.Review access, secrets and incident procedures immediately.

Release sources

  • Runtime contract: OpenAPI document.
  • Compatibility policy: API versioning.
  • Repository history: GitHub commits.
  • Service incidents: status documentation.

How releases are communicated

  1. The changelog identifies the affected surface and whether the entry is documentation, contract, security or runtime behavior.
  2. The OpenAPI document records the route and schema contract for the running deployment.
  3. Migration notes explain required client changes, rollout order and rollback conditions.
  4. Security-sensitive changes include credential, tenant, audit and incident-response actions.
  5. Status incidents remain separate from planned releases and are recorded in the status documentation.

Before adopting a change

QuestionWhere to verify
Does the route or schema exist?Fetch the deployment's OpenAPI document.
Will credentials or scopes change?Review authentication and security guidance.
Can the client retry safely?Review idempotency, errors and rate limits.
Could data visibility change?Review tenant isolation and authorization behavior.
