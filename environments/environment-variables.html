Environments

Environment variables

Environment variables configure identity, storage, brokers, public routing and optional infrastructure overlays. Keep values in the ignored root .env or an approved secret manager; never bake secrets into images or commit them to git.

Secret boundary

Variable names may be documented. Secret values must remain in runtime configuration and must never appear in screenshots, logs, container images, commits or support tickets.

Configuration layers

Base settings establish connectivity; environment overlays select the correct database, listeners, credentials and public route.

Validation procedure

  1. Copy the environment-specific template into the ignored local configuration.
  2. Check required variables are present without printing their values.
  3. Run config --quiet and inspect the selected environment.
  4. Verify database, Redis, Kafka and public URL connectivity separately.
  5. Start services only after reviewing the merged configuration.

Common configuration failures

  • Using a host name reachable only from inside a container on the host machine.
  • Pointing staging workers at a production broker or database.
  • Changing a signing key without coordinating token invalidation.
  • Putting a complete secret-bearing URL in logs or support tickets.
  • Assuming an unset optional variable has the same default in every overlay.
