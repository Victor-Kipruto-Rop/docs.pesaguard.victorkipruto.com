Environments

Production

Production is the authoritative environment for live tenant data, provider callbacks and reconciliation outcomes. It requires separate credentials, reviewed network exposure, tested backups and strict change discipline.

Production posture

Every change must be observable, reversible and supported by an owner who can explain its effect on live reconciliation.

Production entry criteria

  • Staging tests pass for authentication, tenant isolation, validation, idempotency and reconciliation.
  • Production credentials have named owners, least-privilege scopes, expiry and rotation evidence.
  • Database backups and restore procedures have been verified.
  • Monitoring covers API errors, queue lag, broker health, reconciliation outcomes and provider delivery.
  • Rollback, incident contacts and change approval are documented.

Production deployment sequence

  1. Freeze and review the exact artifact and configuration.
  2. Verify the destination URL, database, Redis, Kafka and secret references.
  3. Apply backward-compatible migrations before application rollout.
  4. Deploy with controlled worker concurrency and observe health signals.
  5. Run an authenticated read-only smoke test.
  6. Enable writes or provider callbacks only after metrics remain healthy.
  7. Record release evidence and monitor reconciliation after the change.

Operational safeguards

AreaProduction expectation
SecretsStored server-side, environment-specific and rotated without source changes.
DataNo unapproved test data or destructive experiments.
AccessHuman and service access is least-privilege and auditable.
RecoveryBackups, restore tests, dead-letter handling and reconciliation replay are available.
ChangesReviewed, observable, reversible and announced when compatibility is affected.

Incident response

When production behavior is uncertain, stop new writes or callbacks if required, preserve request and event ids, assess reconciliation impact, and communicate through the status process. Do not repair financial records with ad-hoc database edits; use an auditable correction workflow.
