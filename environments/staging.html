Environments

Staging

Staging is a real deployment used to exercise integration behavior before production. It has its own database, Redis configuration, Kafka listeners, credentials and operational data.

Promotion gate

Staging is complete when the integration is not only functional, but observable, replayable and isolated.

CONTRACT TESTSFAILURE TESTSISOLATION

Developer focus

Contract fixtures, validation, authentication, retries, idempotency and error handling.

Operator focus

Queue lag, broker health, audit events, reconciliation outcomes and reset procedures.

What staging should prove

CapabilityProof
AuthenticationStaging credential succeeds; expired and insufficient-scope cases fail correctly.
IngestionProvider callbacks are validated, persisted and deduplicated.
ReconciliationMatched, unmatched and exception outcomes are explainable.
ReliabilityTimeouts, retries, dead letters and replay preserve event identity.
IsolationStaging cannot read production data or publish to production topics.

Staging test cycle

  1. Apply the reviewed configuration and migrations.
  2. Check service health, database connectivity, Redis and Kafka listeners.
  3. Run contract and integration tests with synthetic data.
  4. Inspect logs, metrics, audit events and reconciliation reports.
  5. Record failures and evidence before approving promotion.

Staging reset and retention

Reset or clean staging deliberately. Preserve enough data to reproduce active failures, but remove expired credentials, stale provider connections and unnecessary personal data. A reset must not invalidate a production credential or affect production brokers.

Promotion gate

Production promotion requires passing staging tests, a reviewed artifact, environment-specific secrets, rollback evidence and an owner for post-deployment observation. See production and the production checklist.
