Errors

Error codes

Stable error codes are the machine-readable part of the failure contract. Message copy helps people, but it can change; client logic must branch on status and code rather than matching prose.

See API · Errors for the envelope and client behaviour.

Code catalog

Code familyTypical statusMeaningClient response
AUTHENTICATION_FAILED401Credential missing, malformed, expired or rejected.Renew or replace credentials once.
FORBIDDEN403Principal lacks scope or tenant access.Correct authorization; do not retry blindly.
VALIDATION_FAILED400 / 422Payload or query violates the contract.Use field details to correct input.
NOT_FOUND404Resource is absent within authorized scope.Confirm id and tenant context.
CONFLICT409Operation conflicts with existing state or key.Read the existing outcome.
RATE_LIMITED429Request budget is exhausted.Back off with jitter.
INTERNAL_ERROR500Unexpected service failure.Bounded retry and escalate with request id.

Compatibility rules

  • Unknown codes must be handled as their status family, not as success.
  • Messages may be localized, reworded or made safer without changing the code.
  • New fields in details are additive; clients should ignore fields they do not understand.
  • Never expose raw error objects containing secrets or internal stack traces to end users.
