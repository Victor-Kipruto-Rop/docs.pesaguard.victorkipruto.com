Errors

429 · Rate limit

The request budget for a credential, tenant, route or downstream dependency has been exhausted. Stop sending work, reduce concurrency and resume only after the server's retry guidance permits it.

See API · Errors for the envelope and client behaviour.

Response handling

HTTP/1.1 429 Too Many Requests
  Retry-After: 10
  Content-Type: application/json
  1. Honor Retry-After when present.
  2. Otherwise use exponential backoff with jitter.
  3. Share a limiter across workers so concurrency actually decreases.
  4. Retry writes only with the original idempotency key.
  5. Alert on sustained throttling instead of increasing retry volume.

What not to do

  • Do not retry every worker at the same fixed interval.
  • Do not increase page size or concurrency after a limit response.
  • Do not treat a 429 as proof that the request was never accepted; inspect idempotent outcomes for writes.
