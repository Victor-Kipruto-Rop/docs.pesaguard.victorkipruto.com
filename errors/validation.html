Errors

400 / 422 · Validation

The request was understood but cannot be accepted because its syntax, schema, format or domain values are invalid. Validation errors are actionable: correct the named field rather than retrying unchanged input.

See API · Errors for the envelope and client behaviour.

400 versus 422

StatusTypical meaning
400Malformed JSON, unsupported query parameter, invalid method or transport-level request.
422Well-formed request violates schema or domain rules such as amount, currency or state.

Example details

{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Request validation failed.",
    "request_id": "request_01J...",
    "details": [
      {"field": "amount", "reason": "must be greater than zero"},
      {"field": "currency", "reason": "must be an ISO 4217 code"}
    ]
  }
}

Client checklist

  • Validate locally for quick feedback, but treat the server as authoritative.
  • Use exact enum, timestamp, currency and identifier formats.
  • Represent financial amounts without binary floating-point surprises.
  • Do not silently coerce invalid values or retry unchanged input.
  • Preserve the request id when asking for help.
