Getting started

Getting started

A guided path from your first health check to a production-ready reconciliation integration. Follow the sequence in order when setting up a new tenant; use the individual pages as runbooks during implementation and release review.

Onboarding path

Establish access, prove the API contract, exercise a real test environment, then promote only after the operational evidence is complete.

01 · ACCESS02 · VERIFY03 · PROMOTE

For developers

Start with health, OpenAPI, credentials, bearer headers, scopes, idempotency and error handling.

For operators

Confirm tenant scope, staging isolation, secrets, backups, observability, rollback and reconciliation ownership.

Start with the quickstart — one health check and one OpenAPI read against a running deployment. Then your first authenticated request introduces the bearer-token pattern and the scope model that governs everything else.

Definition of ready

MilestoneEvidence
Access readyTenant, named users, environment and least-privilege credential are confirmed.
Integration readyAuthenticated reads, validation failures, retries and errors are covered by tests.
Reconciliation readyMatched, unmatched and exception paths have been exercised with traceable evidence.
Production readySecrets, backups, monitoring, rollback and ownership are reviewed and recorded.

Choose your next step

New to the deployment? Start with Quickstart. Joining an existing pilot? Review account provisioning and credential handling. Preparing a release? Go directly to the production checklist.
