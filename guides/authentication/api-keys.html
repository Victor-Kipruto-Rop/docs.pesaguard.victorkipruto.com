Authentication guides

API keys

Use one scoped, expiring API key per integration or service account. Keys identify a workload; tenant membership and scopes determine what that workload may do.

Credential rule

Separate ownership makes least privilege, rotation and compromise response measurable.

SCOPEDEXPIRINGSERVER-SIDE

Before issuance

  • Name the integration and owner.
  • Select environment and tenant.
  • List required read, write or export operations.
  • Set expiry, rotation date and emergency contact.

Use the key safely

Authorization: Bearer <api-key>
  Accept: application/json

Store the raw value only in an approved secret manager. Log the key id and request id, never the secret.

Verify access

  1. Make a read-only staging request.
  2. Confirm the response belongs to the intended tenant.
  3. Test an out-of-scope route and expect 403.
  4. Record the result before enabling writes.

Scopes, expiry, rotation metadata, and one credential per integration.
