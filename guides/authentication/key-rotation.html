Authentication guides

Key rotation

Rotate credentials before expiry and immediately when compromise is suspected. The safe sequence issues the replacement first, verifies it, then revokes the old key.

Rotation without downtime

Use a short overlap window, observe the replacement, and keep an auditable record of who changed what.

ISSUEVERIFYREVOKE

Standard rotation

  1. Inventory the current key id, owner, tenant, scopes and expiry.
  2. Issue a replacement with equal or narrower scopes.
  3. Deploy it through the server-side secret path.
  4. Run authenticated read and write smoke tests in the target environment.
  5. Observe old-key traffic, then revoke it.
  6. Record completion and remove the old secret from runtime configuration.

Compromise response

Revoke first when exposure is suspected; do not wait for a replacement. Preserve audit and access evidence, assess affected tenants and scopes, issue a replacement, and review activity during the exposure window.
