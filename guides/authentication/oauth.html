Authentication guides

OAuth

OAuth is not supported as a public PesaGuard integration flow today. Service access uses scoped bearer tokens or provisioned API credentials issued per deployment.

Do not implement from assumption

Do not send OAuth client credentials, authorization codes or refresh-token requests to an endpoint unless the deployment publishes that contract.

Supported alternative

  1. Request a tenant-scoped service credential through the pilot or deployment operator.
  2. Store it server-side and assign least-privilege scopes.
  3. Send it with the documented bearer header.
  4. Rotate and revoke it using the key lifecycle procedure.

When OAuth becomes available

An OAuth release would need a documented authorization server, issuer and audience, grant types, redirect policy, token lifetime, scopes, revocation behavior and migration plan. Treat those as explicit contract requirements, not implied functionality.
