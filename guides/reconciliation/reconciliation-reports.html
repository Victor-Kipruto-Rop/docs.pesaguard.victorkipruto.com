Reconciliation guides

Reconciliation reports

A reconciliation report should be a view of durable reconciled records, not a second matching engine. Reports must agree with exception queues, audit decisions and the tenant-scoped API.

One source of truth

Build reports from the reconciled outcome and preserve the filters, time window, sort and generation timestamp.

Report definition

FieldRequired context
ScopeTenant, provider flow and environment.
WindowUTC start and end boundaries.
Outcome countsMatched, unmatched, exception and resolved totals.
EvidenceGeneration time, filters, sort and source query or export id.

Reconcile report totals

  1. Freeze the query and record its filters.
  2. Use stable sorting and complete pagination.
  3. Compare totals with the exception queue and audit events.
  4. Investigate mismatches before publishing the report.
  5. Retain the report evidence according to tenant retention policy.

Reports read the reconciled record and its exceptions, so the queue and the numbers agree.
