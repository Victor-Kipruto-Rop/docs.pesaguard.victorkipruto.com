Transaction guides

Handle failures

Failure handling is part of the transaction workflow. Classify the response, preserve the request id, retry only when safe and reconcile any write whose outcome is uncertain.

Recover without duplication

Network failure is not proof that a financial operation failed. Preserve identity first, then determine the durable outcome.

CLASSIFYBACKOFFRECONCILE

Failure decision table

ResponseAction
400 / 422Correct input; do not retry unchanged.
401 / 403Renew credentials or correct permission and tenant context.
409Read the existing operation or state.
429Honor retry guidance and reduce concurrency.
5xx / timeoutBounded retry; same idempotency key for writes; then reconcile.

Operational checklist

  1. Log status, stable code, request id, route and environment.
  2. Redact credentials and sensitive payloads.
  3. Use exponential backoff with jitter.
  4. Stop after a bounded retry budget.
  5. Escalate persistent or financially ambiguous outcomes with evidence.

Retry with backoff, match on stable codes, and quote the request id.
