Transaction guides

Search transactions

Search is a bounded, tenant-scoped read. Combine documented filters with stable sorting and pagination so exports and reconciliation scans do not skip or duplicate records.

Search procedure

  1. Choose a narrow UTC time window.
  2. Add documented status, provider or reference filters.
  3. Set a bounded limit and stable sort.
  4. Record the complete query and page metadata.
  5. Retry a failed page without changing the query.

Export-safe query

GET /api/v1/transactions?status=exception&page=1&limit=50&sort=created_at:asc,id:asc
  Authorization: Bearer <token>

Search safeguards

  • Never rely on insertion order.
  • Do not remove tenant scope from a filter.
  • Use a server export or snapshot for long-running complete exports.
  • Deduplicate by server resource id when scanning changing collections.

Paginate deterministically and treat unspecified ordering as unstable.
