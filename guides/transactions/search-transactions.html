Search transactions

List recent transactions for a tenant, newest first. The endpoint takes one filter, since, and returns at most 200 rows; it has no pagination, status or sort parameters today.

Read pattern

GET/api/v1/customers/{tenant_id}/transactions
GET /api/v1/customers/{tenant_id}/transactions?since=2026-09-20T00:00:00Z
Authorization: Bearer <token>
BehaviorDetail
sinceOptional ISO 8601 timestamp. Returns transactions with created_at at or after it. An invalid value returns 400 invalid_date_format.
Ordering and sizecreated_at descending, capped at 200 rows.
Response{"tenant_id", "items"}; each item has trans_id, trans_amount, msisdn, business_short_code, trans_time, created_at.
Permissionread:discrepancies, and the path tenant must be the caller's tenant.

Scanning safely

  • If a response contains 200 items, older matches may have been cut off. Poll with a recent since often enough that fewer than 200 transactions arrive between polls.
  • Deduplicate by trans_id, because overlapping polls return the same rows.
  • Fetch a single transaction for its raw payload and matched record.
Planned. Filtering by status, provider or reference, page and limit pagination, and a sort parameter have no implementation on this route today. For the discrepancy list, use GET /discrepancies with page and per_page.
