Transaction guides

Transaction status

A transaction status tells you what has been proven so far, not necessarily that funds have settled. Read the state with its reconciliation result, provider evidence and audit trail.

Status is evidence

Use state transitions to drive workflow, never to bypass validation or reviewer controls.

STATEEVIDENCEAUDIT

State handling

StateClient behavior
ReceivedWait for matching or follow the documented event flow.
MatchedUse the recorded evidence and continue downstream processing.
UnmatchedInspect the reason; do not mark successful manually.
ExceptionRoute to a reviewer with the delta and context.
ResolvedUse the recorded decision and audit evidence.

Polling guidance

Use bounded polling with backoff for asynchronous state changes. Prefer webhook delivery when available, and always make the consumer idempotent because notifications can be retried.

See the lifecycle concept page for states and their preconditions.
