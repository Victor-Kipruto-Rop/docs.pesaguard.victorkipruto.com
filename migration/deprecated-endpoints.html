Migration

Deprecated endpoints

No endpoints are currently listed as deprecated. When a route enters a deprecation window, this page should identify the replacement, affected versions, first notice date, sunset date and migration owner.

Deprecation is a managed transition

An endpoint remains usable during its support window, but new integrations should move to the replacement immediately.

FieldWhy it is required
Old route and versionDefines exactly what consumers must find.

Notice and sunset datesCreates a measurable support window of at least 90 days.
Owner and support pathGives consumers a place to resolve migration blockers.

Consumer response

  1. Inventory usage of the deprecated route.
  2. Compare old and replacement contracts.
  3. Update tests for authentication, validation, errors and retries.
  4. Roll out the replacement with metrics and rollback.
  5. Confirm old-route traffic reaches zero before sunset.

Current status

No endpoint is listed as deprecated in the current documentation set. Continue using the documented route versions and check the changelog and running OpenAPI reference for future notices.

How to detect usage

  • Search source code, generated clients and infrastructure configuration for the old route.
  • Measure request counts by route, version, tenant, credential and client release.
  • Include background workers, scheduled exports and support tools in the inventory.
  • Track traffic until it remains at zero through the final support window.

Deprecation announcement template

Deprecated: GET /api/v1/example
  Replacement: GET /api/v2/example
  Notice date: YYYY-MM-DD
  Sunset date: YYYY-MM-DD
  Behavior changes: ...
  Migration owner: ...
  Support path: ...

Provider and client impact

Deprecation can affect more than direct callers. Review SDKs, webhooks, exports, dashboards, audit queries and reconciliation jobs before declaring a migration complete.
