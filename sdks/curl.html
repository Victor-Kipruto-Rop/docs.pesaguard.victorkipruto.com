SDKs

curl

Use curl for the smallest reproducible request, deployment health checks and support diagnostics. Every command should identify its environment without exposing credentials.

Reproducible HTTP

Start with curl before introducing a generated client. It separates API behavior from application-library behavior.

DEBUGVERIFYREPRODUCE

Health and contract

curl --fail-with-body "$PESAGUARD_API_URL/health"
curl --fail "$PESAGUARD_API_URL/openapi.json" -o openapi.json

Authenticated request

curl --fail-with-body "$PESAGUARD_API_URL/api/v1/tenant/current" \
  -H "Authorization: Bearer $PESAGUARD_ACCESS_TOKEN" \
  -H "Accept: application/json" \
  -H "X-Request-ID: support-check-001"

Safe write pattern

curl --fail-with-body -X POST "$PESAGUARD_API_URL/api/v1/transactions" \
  -H "Authorization: Bearer $PESAGUARD_ACCESS_TOKEN" \
  -H "Idempotency-Key: transaction-create-001" \
  -H "Content-Type: application/json" \
  --data @transaction.json

Never reuse an idempotency key for a different logical operation. Save the response request id for correlation.

Debugging checklist

  1. Confirm the URL and environment.
  2. Use --fail-with-body so error responses remain visible.
  3. Inspect status and stable error code, not only prose.
  4. Redact the Authorization header before sharing output.
