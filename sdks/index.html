SDKs and client libraries

There are no official PesaGuard SDKs yet. The supported integration surface is the deployment's OpenAPI contract, which you can call with any HTTP client or use to generate a language-specific client.

Build on the contract

Keep authentication, retries, idempotency, tenant context and error handling in your own thin client boundary.

OPENAPIHTTPGENERATED
Support boundary

Generated clients are implementation aids, not a guarantee that every runtime behavior is encoded in types. The running deployment's OpenAPI document and behavior remain authoritative.

GETgenerate a client
curl -sS "$PESAGUARD_API_URL/openapi.json" -o openapi.json
# example: generate a Python client
npx @openapitools/openapi-generator-cli generate \
  -i openapi.json -g python -o ./client

Official clients (Python, TypeScript, JavaScript) will follow once the v1 contract is verified in production. A client generated from the published spec is the supported path until then.

Client responsibilities

  1. Load the correct environment base URL and credential at runtime.
  2. Send bearer credentials over HTTPS without logging secrets.
  3. Apply timeouts and bounded retries with jitter.
  4. Reuse idempotency keys for uncertain writes.
  5. Parse stable error codes, preserve request ids and redact payloads.
  6. Keep tenant context and API version explicit in telemetry.

Generated-client review

Before production use, inspect generated authentication, timeout, serialization, pagination and exception behavior. Add contract tests for 401, 403, 409, 429 and 5xx responses, then pin the OpenAPI input used for generation.
