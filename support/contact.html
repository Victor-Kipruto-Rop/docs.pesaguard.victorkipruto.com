Support

Contact support

Use the right channel for the kind of help you need. Pilot support is handled directly today; documentation and security reports follow separate paths so sensitive information stays private.

Send the right context

A concise, redacted report reaches resolution faster than a screenshot without an environment or request id.

Do not send

  • Passwords, API keys, bearer tokens or signing secrets.
  • Full authorization headers or unredacted payment payloads.
  • Personal data that is not required to reproduce the issue.
  • Public issue posts containing vulnerability details.

Before you contact support

  1. Check the status page for an active incident.
  2. Reproduce in the same environment without changing the request repeatedly.
  3. Capture one representative request id and stable error code.
  4. Remove credentials and unnecessary personal or payment data.
  5. State whether the issue is blocking writes, delaying reconciliation or limited to a read.

Security report procedure

Use private responsible disclosure for vulnerabilities. Describe the affected component, security impact, minimal reproduction, prerequisites and remediation suggestion. Allow the team to acknowledge and investigate before publishing details.
