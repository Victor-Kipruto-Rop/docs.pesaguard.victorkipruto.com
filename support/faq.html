Support

Frequently asked questions

Straight answers about scope, access, integrations, support and operational boundaries. When an answer depends on deployment configuration, confirm it against the running OpenAPI contract or environment configuration.

Read the boundary before building

Knowing what is supported today prevents an integration from depending on an assumed capability.

Product and access

Is there public self-serve signup?

Not currently. Tenant access and reconciliation scope are provisioned with the pilot team.

Which payment rails are supported?

The current pilot scope is M-Pesa Daraja flows. Airtel Money, bank transfers and card rails require separate scoping.

Is there a mocked sandbox?

No. Staging is a real isolated deployment with its own data stores, credentials and brokers. See staging.

Developer questions

Are official SDKs available?

Not yet. Use the deployment OpenAPI document with curl, a generated client or the examples in the SDK section.

How should writes be retried?

Use one idempotency key for one logical operation, retry with bounded backoff and reconcile if the response is uncertain.

Which source is authoritative?

The running deployment's OpenAPI document is authoritative for routes and schemas. This documentation explains surrounding behavior and operational expectations.

Security and assurance

Does PesaGuard claim a certification?

No certification should be inferred from this documentation. Review the security controls and assess them against your organization's requirements.

How do I report a vulnerability?

Use the responsible disclosure process and do not publish exploit details or secrets in public issues.

Support and incidents

What should I send with a failure?

Send environment, UTC timestamp, route, status, stable error code, request id and a redacted reproduction. Never send raw tokens or passwords.

Environments and operations

How do I know which environment I am calling?

Check PESAGUARD_API_URL, credential ownership, database and broker configuration, then run a safe authenticated read. Never infer environment from a key prefix alone.

What should I do during a 429?

Honor Retry-After, reduce concurrency and use jitter. For writes, preserve the same idempotency key.

What should I do after a 5xx or timeout?

Treat a write outcome as uncertain. Retry only with the original idempotency key, then retrieve or reconcile the resulting record.

Data and reconciliation

Why is a transaction unmatched?

The provider event did not find a valid internal candidate within the configured matching window. Review reference, amount, currency, timing and tenant before replaying.

Can support edit a financial record directly?

Corrections should use an auditable workflow. Do not rely on ad-hoc database changes that erase the original event or reviewer decision.

Documentation lifecycle

What happens when documentation and runtime behavior differ?

Use the running deployment's OpenAPI contract as the route and schema authority, preserve the discrepancy, and report the page URL and observed behavior so the documentation can be corrected.

Where are breaking changes announced?

Review the changelog, migration guides and API versioning policy before upgrading a client.
