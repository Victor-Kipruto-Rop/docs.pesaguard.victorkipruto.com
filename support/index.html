Support

A practical support center for developers, operators and pilot teams. Start with the right evidence, follow the relevant runbook and escalate with enough context for an operator to reproduce the problem.

Support without guesswork

Check service state, classify the failure, preserve correlation ids and send a concise reproduction.

DIAGNOSEDOCUMENTESCALATE

Technical support

For API failures, integration questions and production behavior. Start with Troubleshooting, then send request ids and redacted evidence.

Documentation

For unclear or incorrect guidance, check the running API contract and report the page plus the expected correction.

Security

For vulnerabilities, exposed credentials or tenant-isolation concerns, use private disclosure, never a public issue.

First five minutes

  1. Check service status and confirm the environment.
  2. Capture the UTC time, route, status, stable error code and request id.
  3. Check the matching error guide before retrying.
  4. Preserve the same idempotency key for an uncertain write.
  5. Escalate with a redacted reproduction and clear impact statement.

What to include in every report

  1. Environment and base URL, without credentials.
  2. Tenant or service identity, using a safe identifier.
  3. UTC timestamp and request, event or transaction id.
  4. HTTP method, route, status and stable error code.
  5. Minimal redacted request and response example.
  6. Expected result, actual result and whether a retry was attempted.

Support boundaries

PesaGuard is currently supported through the pilot team and repository channels rather than a public ticket portal. Never send passwords, API keys, bearer tokens, personal data or full authorization headers in a support request.
