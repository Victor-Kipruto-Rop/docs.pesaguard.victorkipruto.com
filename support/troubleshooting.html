Troubleshooting

A structured path from symptom to evidence. Start with the request id and environment, classify the status, then follow the narrowest recovery action instead of repeating an unknown failure.

Diagnose in layers

Environment first, identity second, contract third, durable outcome last.

CONTEXTCLASSIFYRECOVER

Quick triage

1. Context

Confirm environment, URL, tenant-safe identity, UTC time and whether the issue affects reads, writes or callbacks.

2. Classification

Use status and stable error code to choose a recovery path. Do not retry an unknown failure indefinitely.

3. Evidence

Preserve request, transaction or event ids, then compare the durable state and audit trail.

When the issue is a data outcome

Do not repair an uncertain transaction by issuing another write. Retrieve the current state, inspect provider and reconciliation evidence, preserve the idempotency key and escalate with the transaction or event id.

Escalate immediately

  • Cross-tenant data appears in a response, export or log.
  • A retry may have produced duplicate financial records.
  • Credentials or signing secrets may be exposed.
  • Reconciliation results differ without an explainable rule change.
