Testing

Failure scenarios

Failure tests prove that bad input, duplicate delivery, dependency outages and tenant mistakes become visible, recoverable outcomes rather than silent corruption.

Break it deliberately

Inject one failure at a time, capture the evidence and assert the durable result before moving to the next scenario.

Failure matrix

ScenarioInjectAssert
Duplicate deliverySend the same event or idempotency key twice.One durable record, one audit outcome and a safe duplicate response.
Malformed payloadRemove required fields or change types.400/422 with field reason; no reconciliation side effect.
Consumer downtimeStop the worker or receiver.Retry and dead-letter state preserve event identity.
Tenant violationUse another tenant's identifier or filter.Empty or forbidden result with no data disclosure.
Timeout after writeDrop the client response after submission.Same-key retry returns one original outcome.
Out-of-order eventDeliver state changes in reverse order.State guards prevent regression and preserve audit evidence.

Pass criteria

  • No duplicate financial record.
  • No cross-tenant data exposure.
  • No silently discarded event or exception.
  • Recovery remains bounded and observable.
  • Operator can explain the outcome from retained evidence.
