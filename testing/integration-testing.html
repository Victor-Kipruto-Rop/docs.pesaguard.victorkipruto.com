Testing

Integration testing

Integration tests exercise real service boundaries: database persistence, asynchronous workers, Kafka or provider events, Redis-backed work and tenant-aware authorization.

Integration setup

  1. Use an isolated staging tenant and environment credential.
  2. Provision synthetic provider and internal records.
  3. Start API, database, workers, Redis and broker dependencies.
  4. Capture request, event, transaction and audit identifiers.
  5. Reset only through a controlled fixture or cleanup procedure.

Invariants to assert

InvariantAssertion
Exactly-once logical writeRepeated delivery does not create a second financial record.
Tenant isolationEvery read, write, export, event and cache access is scoped.
Durable acknowledgementSuccess is returned only after required state is persisted.
Explainable decisionMatch, exception or review outcome has evidence and reason.
Replay safetyDead-letter replay preserves identity and produces one outcome.

Test artifacts

Keep fixtures, environment version, contract version, test timestamps, logs, metrics, audit events and failure traces together. A test that cannot be reproduced is a signal, not durable evidence.
