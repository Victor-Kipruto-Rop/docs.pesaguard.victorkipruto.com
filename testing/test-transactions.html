Testing

Test transactions

Create controlled staging transactions and assert the full outcome: authenticated ingestion, durable persistence, matching decision, exception reason, audit event and downstream notification.

Transaction test matrix

FixtureExpected result
Exact reference and amountMatched with evidence for reference, amount, currency and time.
Amount differenceException with an explicit delta; no silent rounding.
Missing internal candidateUnmatched queue entry with reason and provider event identity.
Duplicate callbackOne transaction and one logical audit outcome.
Late callbackConfigured tolerance determines match or review path.

Assertion sequence

  1. Verify callback signature or API credential.
  2. Confirm event and transaction records are durable.
  3. Read lifecycle state and reconciliation outcome.
  4. Inspect audit entry and reviewer context.
  5. Confirm webhook or report reflects the same outcome.

Test data hygiene

Use synthetic references, amounts and identities. Keep fixture ownership and cleanup explicit; never use production credentials or copy production personal data into staging.
